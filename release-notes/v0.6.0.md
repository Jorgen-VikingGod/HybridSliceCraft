**HybridSliceCraft 0.6.0** makes slicing for resin printers much faster and lighter on memory.

## Faster resin slicing

Slicing the Stanford dragon (318,000 triangles, 1,941 layers) for a 16K screen (15120 × 6230) takes about 0.22 s with no anti-aliasing, down from roughly 1.6 s. With 3×3×3 anti-aliasing it takes about 1.0 s, down from roughly 4.8 s. Those are slicing times alone, measured on a 20-thread processor.

On a 12K screen (11520 × 5120) the dragon is sliced and saved as a `.goo` file in about 0.16 s, or 0.85 s with 3×3×3 anti-aliasing. A 7.5 million triangle model takes about 0.7 s and 3.5 s.

- **Layer drawing** only works on the places where a shape's edges are, instead of walking every lit pixel of every row. This is where most of the time went.
- **Less memory**: each processor thread reuses its working space instead of allocating it again for every layer. Peak memory with anti-aliasing is about a third lower.
- **Floating-part check** converts each layer once instead of two or three times.
- **Trapped-resin check** only looks at the area around the model, and its search is faster.
- **Sorting triangles into layers** now uses all processor threads.

The pictures that come out are exactly the same as before, and so are the floating parts and trapped-resin results.

## New

- **Benchmark mode**: `hybridslicecraft --bench-resin <model>` slices without opening a window and prints the time, peak memory and a checksum of the result. It takes `--aa`, `--z-samples`, `--layer-height`, `--res`, `--screen`, `--runs` and `--export <file>`. Run `--help` for details.

## Not changed

Loading very large model files is still slow: a 7.5 million triangle file takes about 1.2 s to open. Saving PNG-based files (SL1 and PNG stack) is also not faster yet.

None of the saved files have been tried on a real printer yet. Check a small print first.
